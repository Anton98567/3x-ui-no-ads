# 3x-ui-no-ads — убираем рекламу из панели 3X-UI

Убирает встроенные **рекламные (sponsor) карточки** из веб-панели 3X-UI — со страницы
логина, с главной страницы (дашборда) и из раздела «Sponsors». Не трогает ядро панели,
базу данных, inbounds и клиентов — **VPN/прокси-подключения не затрагиваются вообще**.
Полностью обратимо.

---

## 1. Куда вшита реклама

Реклама — это встроенная фича **«Sponsors»** самой 3X-UI (платные партнёрские карточки,
например кампании вида *YadrenoVPN* с датами показа `from`/`until`). Устроена так:

* **Фронтенд (браузер):** React-компоненты `SponsorSlot` и `SponsorCard`, вшитые в бинарник
  панели (`internal/web/dist/assets/SponsorSlot-*.js`, `SponsorCard-*.js`). Они рисуют
  карточку-ссылку с кнопкой «visit» (теги `.sponsor-card`, `.sponsor-logo`, `.sponsor-visit` …).
* **Где рисуются:**
  * страница **логина** → `<SponsorSlot slot="login">` (обёртка `.login-sponsor`);
  * **главная страница / дашборд** → `<SponsorSlot slot="dashboard">`;
  * отдельный пункт меню **«Sponsors»** (`/sponsors`).
* **Откуда данные:** компонент делает запрос `GET <base>/sponsors` к бэкенду панели
  (`{"contact":…,"sponsors":[{id,name,slots,logo,title,text,link,…}]}`). Бэкенд, в свою
  очередь, периодически подтягивает **удалённый sponsor-фид** и кэширует его.

**Ключевое свойство:** если список спонсоров пуст, `SponsorSlot` возвращает `null` и
**не рисует ничего** (`if (f.length === 0) return null;`). Поэтому достаточно заставить
эндпоинт `/sponsors` возвращать пустой список — и реклама исчезает со всех страниц разом.

---

## 2. Как работает патч

Патч **не трогает бинарник и БД**. Он перехватывает запрос `/sponsors` на обратном
прокси **nginx** (панель всегда стоит за nginx) и отдаёт пустой список спонсоров:

```nginx
location = /my-3x-panel/sponsors {
    default_type application/json;
    add_header Cache-Control "no-store" always;
    return 200 '{"success":true,"msg":"","obj":{"contact":"","sponsors":[]}}';
}
```

Фронтенд получает пустой список → компонент рендерит `null` → рекламы нет на логине,
на дашборде и в разделе «Sponsors».

Почему это безопасно для клиентов:

* меняется **только** конфиг nginx для админского эндпоинта `/sponsors`;
* не изменяются `x-ui.db`, inbounds, клиенты, конфиг xray и сам процесс проксирования;
* клиентские подписки (`/sub/`, `/json/`, `/clash/`, `/my-post-key/…`) и туннели не трогаются.

## 3. Установка / использование

### Одна команда (рекомендуется)

Скрипт сам находит панель и base-path — просто выполните на сервере с 3X-UI:

```bash
curl -fsSL https://raw.githubusercontent.com/Anton98567/3x-ui-no-ads/main/3x-ui-no-ads.sh | sudo bash
```

Если авто-определение не сработало (редко) — укажите адрес панели явно:

```bash
curl -fsSL https://raw.githubusercontent.com/Anton98567/3x-ui-no-ads/main/3x-ui-no-ads.sh | sudo bash -s -- --url https://your-host/my-3x-panel/
```

После выполнения откройте панель и нажмите **Ctrl+F5**, чтобы браузер выббросил
закэшированную карточку.

### Пошагово (локальный файл)

Скопируйте `3x-ui-no-ads.sh` на сервер и запускайте от `root`:

```bash
# 1) снять рекламу
sudo ./3x-ui-no-ads.sh apply

# 2) проверить, что реклама отключена и клиенты целы
sudo ./3x-ui-no-ads.sh verify

# 3) (по желанию) показать текущее состояние
sudo ./3x-ui-no-ads.sh status

# 4) полностью откатить патч (реклама вернётся)
sudo ./3x-ui-no-ads.sh remove
```

### Параметры

| Параметр | Назначение |
|---|---|
| `apply` / `verify` / `remove` / `status` | команда (по умолчанию `apply`) |
| `--url <url>` | публичный адрес панели вместе с base-path (рекомендуется) |
| `--base-path <path>` | base-path панели, напр. `/my-3x-panel` (перекрывает `--url`) |
| `--conf <file>` | файл конфига nginx с серверным блоком панели (иначе — автопоиск) |
| `--dry-run` | только показать, что будет изменено, ничего не писать |
| `-y`, `--yes` | не спрашивать подтверждение |

Скрипт сам находит base-path, файл конфига nginx и нужный `server`-блок, вставляет
блок с маркерами `# >>> 3x-ui-no-ads >>> … # <<< 3x-ui-no-ads <<<` (идемпотентно) и
делает `nginx -t` + `systemctl reload nginx`. Перед изменением конфига создаётся бэкап
`*.bak-3xui-no-ads-<дата>`.

---

## 4. Проверка результата

* `curl -s https://your-host/my-3x-panel/sponsors` должен вернуть
  `{"success":true,"msg":"","obj":{"contact":"","sponsors":[]}}` — пустой список.
* В браузере (Ctrl+F5) на логине, на дашборде и в разделе «Sponsors» нет рекламных карточек.
* `sudo ./3x-ui-no-ads.sh verify …` печатает `VERIFY PASSED` и проверяет, что службы
  `x-ui`/`nginx` активны.

---

## 5. Откат

```bash
sudo ./3x-ui-no-ads.sh remove
```

Удаляет вставленный блок из конфига nginx и перезагружает nginx. Реклама возвращается
после перезагрузки страницы. Конфиг также можно вернуть из бэкапа `*.bak-3xui-no-ads-*`.

---

## 6. Важные замечания

* **Требуется nginx перед панелью** (стандартная схема). Если панель напрямую открыта на
  порту (без nginx), перехватить API этим способом нельзя — тогда проще всего закрыть
  доступ к `/sponsors` файрволом/`hosts`, либо поставить панель за nginx.
* Патч **переживает ребуты и `reload nginx`** (изменение в файле конфига), но может
  пропасть, если конфиг nginx будет пересоздан/перегенерирован (например certbot-скриптом,
  перезаписывающим сайт-блок). В этом случае просто повторите `apply`.
* Если на одном сервере несколько панелей 3X-UI на разных base-path — прогоните скрипт
  для каждой со своим `--url`.
* Патч не удаляет саму фичу «Sponsors» из интерфейса (пункт меню останется, но будет
  пустым) — он лишь отключает показ рекламных карточек.
